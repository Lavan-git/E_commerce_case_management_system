# Return Policy

**Document type:** Policy  
**Domain:** Returns  
**Version:** 1.0  
**Status:** Active

## Purpose

This policy defines the general workflow for customer return requests.

## Return request

A customer return case should identify the relevant order and, when applicable, the affected item.

Before approving a return, the support process should verify that the order exists and that the requested return is associated with that order.

## Return approval

When a return is approved:

1. create or update the return record
2. record the reason for the return
3. communicate the next required step to the customer
4. track the return until the expected outcome is recorded

## Return not received

If a customer states that a returned item was sent but the return has not been recorded as received, the case should remain open while the shipment or return status is investigated.

Relevant delivery or shipment information should be used as evidence.

## Return rejected

When a return is rejected, the case should retain the reason for rejection.

A support response should distinguish between:

- return not eligible
- required information missing
- return not received
- other documented rejection reasons

## Refund relationship

Approval of a return does not by itself mean that a refund has been completed.

The refund process must be tracked separately until its final state is confirmed.
