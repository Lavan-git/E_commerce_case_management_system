# Refund Policy

**Document type:** Policy  
**Domain:** Refunds  
**Version:** 1.0  
**Status:** Active

## Purpose

This policy defines the handling of refunds associated with cancelled orders, eligible returns, duplicate payments, and payment reconciliation cases.

## Refund eligibility

A refund may be initiated when a verified business event requires the customer's money to be returned, including:

- an eligible cancelled order
- an approved return
- a confirmed payment issue where no valid order was created
- another explicitly approved refund scenario

## Refund initiation

Before initiating a refund, the agent or service must verify:

1. the payment or order associated with the refund
2. the reason for the refund
3. that the amount to be refunded is supported by the underlying transaction or case
4. that a duplicate refund has not already been initiated

## Duplicate refund prevention

A refund must not be initiated twice for the same eligible financial event.

Existing refund records should be checked before creating another refund action.

## Failed refund initiation

If a refund cannot be initiated successfully, the case should remain open and record the failure reason. The customer should not be told that a refund has been completed until completion is confirmed.

## Refund status

A refund should be treated as completed only when the corresponding refund record indicates a completed state.

A pending refund must remain distinguishable from a completed refund.

## Evidence

Refund cases should retain relevant identifiers and supporting information, such as:

- order identifier
- payment identifier
- refund amount
- refund status
- reason for refund
